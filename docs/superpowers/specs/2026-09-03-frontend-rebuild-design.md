# BUTTON frontend rebuild — design spec

Date: 2026-09-03
Status: Approved by user, ready for implementation planning

## 1. Goal

Rebuild `web/` from a single 735-line dependency-free vanilla JS file into a
production-quality, componentized React app matching the industrial
control-panel visual direction below, while preserving 100% of the existing
onchain/preview behavior (states, polling cadence, timer precision, sound,
chain-time correction).

This is a frontend-only change. `contracts/`, `scripts/deploy.sh`,
`scripts/start.sh`, and the Solidity contract are untouched.

## 2. Non-goals

- No automated test suite (none exists today, none requested — only lint,
  typecheck, build are required checks). Flagged as a follow-up TODO in the
  final report, not built now.
- No change to the on-chain contract, ABI, or deployment scripts.
- No multi-wallet modal (WalletConnect, Coinbase Wallet, etc.) — injected
  wallet only (e.g. MetaMask), same scope as today, now via wagmi's
  injected connector instead of hand-rolled `window.ethereum` listeners.
- No new environment variables beyond what `.env.example` already defines.

## 3. Architecture

- **React 18 + TypeScript (strict) + Vite** — component model matching the
  layout spec directly; `tsc --noEmit` gives the requested typecheck step.
- **viem** — typed contract reads/decoding generated from
  `contracts/ButtonExperiment.abi.json`, replacing the hand-rolled selector
  table and manual hex encode/decode (`encodeUint`, `encodeAddress`,
  `decodeLog`, `KNOWN_SELECTORS`, `hexToBigInt`, `pad64`, `textHex`) in the
  current `web/app.js`.
- **wagmi** — React hooks for account/chain state, connect/disconnect,
  contract reads/writes, replacing the current app's manual
  `ethereum.on("accountsChanged"/"chainChanged")` listeners and imperative
  `connectWallet()`/`switchNetwork()` functions.

### 3.1 Config stays runtime, not build-time

`.env.example` already uses `VITE_*`-prefixed names, but today's
`scripts/configure.mjs` writes them into a plain `window.BUTTON_CONFIG`
object in `web/config.js`, loaded via a `<script>` tag **before** the app
script — decoupled from any bundler. This is deliberate: it lets ops
deploy the site sealed, verify it publicly, and later re-point the exact
same built bundle at a different network/contract (testnet → mainnet)
without a rebuild, matching the phased rollout in `README.md` and
`LAUNCH_CHECKLIST.md`.

**This pattern is preserved exactly.** The React app reads
`window.BUTTON_CONFIG` at runtime (not `import.meta.env`).
`scripts/configure.mjs` is unchanged. `scripts/deploy.sh` and
`scripts/start.sh` are unchanged. The only new file is a static
`config.js` placeholder shipped in `web/public/` so local `vite dev`/
`vite preview` boot in preview mode by default, exactly like today's
`python3 -m http.server` did against the empty `web/config.js`.

### 3.2 Build output / deployment

- Vite project root: `web/`. Build output: `web/dist/`.
- `web/vercel.json` `outputDirectory` (or equivalent Vercel project
  setting) updated to `web/dist` — the security headers config is
  unchanged.
- `scripts/configure.mjs` writes to `web/public/config.js` (dev/pre-build
  source of truth) — Vite copies `public/` verbatim into `dist/`, so the
  generated `config.js` ships alongside the built bundle without being
  processed/inlined by the bundler. Ops workflow in `README.md` stays
  `node scripts/configure.mjs` then redeploy the `dist` output; no rebuild
  required to change network/contract config, exactly as today.

## 5. Component responsibilities (layout spec mapping)

| Region | Component(s) | Contents |
|---|---|---|
| Top nav | `TopBar` | Brand + BUTTON/RDDT pair badge, nav links (Experiment/Lore/Stats), sound toggle, network pill, ConnectWallet button |
| Center | `PressStage` | "LIVE ON ROBINHOOD CHAIN" / experiment-status line, `CountdownDisplay` (segmented LED), `PressButton`, "DON'T PRESS IT" tagline, "One wallet. One press. Resets the timer..." copy, `PressStatusLine` |
| Left column | `LivePressFeed` | Wallet, time pressed, faction, tx link per row; `FeedSkeleton` while loading; `FeedEmptyState` pre-activation |
| Right column | `StatsPanel` | Total presses, closest call, experiment uptime, current streak, `FactionBars` distribution |
| Lower-left | `TokenPanel` | "$BUTTON / RDDT", "the token is the receipt" copy, contract/explorer links, trade link from `tokenUrl` config |

matching current site structure and copy verbatim.

## 6. Data layer detail

All hooks live under `src/hooks/` and are consumed by `App.tsx`, which
holds no rendering logic itself beyond composing the layout — matching
"reusable components... rather than one giant page component."

- `useExperimentState()` — wagmi `useReadContracts` (multicall) for
  `started`, `startedAt`, `deadline`, `totalPresses`, `closestCall`,
  `isAlive`, `factionCounts(1..6)`. Polls every 2500ms (`refetchInterval`),
  matching today's `setInterval(refreshCore, 2500)`. On RPC failure,
  preserves last-known state and surfaces `stale: true` — ports the
  `state.stale` behavior in `refreshCore`'s catch block exactly.
- `usePressFeed()` — `getLogs` for the `Pressed` event from
  `contractDeployBlock` to `latest`, polling every 5000ms, matching
  `setInterval(refreshLogs, 5000)`. Decoded via the ABI's typed event
  (replaces manual `decodeLog`).
- `useUserPress(account)` — reads `hasPressed`, `pressFaction`,
  `pressRemaining` for the connected account when `account` is set and not
  in preview mode.
- `useCountdown()` — `requestAnimationFrame` loop rendering
  hundredths-of-a-second precision, corrected by `chainOffsetMs` (chain
  block timestamp minus local clock, recomputed each `useExperimentState`
  refresh) exactly as today's `nowChainMs()`. Exposes `urgent` (≤12s) and
  `critical` (≤5s) flags and triggers `playTone` once per whole-second tick
  while `urgent` is true and the experiment is alive — ports
  `updateTimer`'s tick logic exactly, including the frequency/gain step at
  ≤5s.
- `usePreviewClock()` — active only when `runtimeConfig.previewMode` is
  true. Local 60s clock starting at mount, one simulated press allowed,
  local fake tape entry, ends at zero — ports the `preview` object and
  `previewPress()` logic as-is, including the `0x0000…VIEW` placeholder
  presser address convention.
- `useStreak(feed)` — **new**, derives "current streak" as the count of
  the most recent consecutive presses sharing the same faction, reading
  backward from the latest press in `usePressFeed`'s decoded log list;
  resets to 1 (or 0 if no presses) on a faction change. Purely
  client-derived, no new contract reads.

## 7. States matrix

Every state below is a distinct rendering branch, primarily inside
`PressStatusLine` (press-related) and `TopBar`/`AppShell` (connection/
network-related), each ported from the corresponding branch in today's
`renderCore()`:

| State | Ported from |
|---|---|
| Preview / no contract configured | `previewMode` branch of `renderCore` |
| Sealed / not started | `!state.started` branch |
| Live | `state.alive` branch |
| Ended forever | `!state.alive` (post-start) branch |
| Disconnected wallet | `!account` guards throughout |
| Wrong network | `wrong = account && walletChainId !== net.chainId` |
| Wallet signature rejected | `press()`'s try/catch on `eth_sendTransaction` rejection |
| Transaction pending | `press()`'s pending state before receipt |
| Transaction reverted/failed | `waitForReceipt` failure branch |
| Already pressed | `already = account && userState.hasPressed` |
| RPC stale (preserve last-known state) | `state.stale` branch |
| Empty tape | `tape.length === 0` in `renderTape` / `FeedEmptyState` |
| Loading skeletons | **new** — `FeedSkeleton`, `StatTile` loading variant, shown before first successful `useExperimentState`/`usePressFeed` resolution |

The exact button label progression (`WAIT` → `SEALED`/`PRESS`/`SWITCH`/
`SPENT`/`ENDED`/`STALE`) from `setPressButton` calls in `renderCore` is
preserved.

## 8. Design system

- `src/styles/tokens.css` ports the existing `:root` custom properties
  verbatim: `--bg #080808`, `--panel`/`--panel-2`, `--ink`, `--muted`,
  `--line`, `--red #ef2b24`/`--red-dark`, faction colors (`--purple
  #8b5cf6`, `--blue #3b82f6`, `--green #22c55e`, `--yellow #f4d03f`,
  `--orange #f97316`, `--faction-red #ef4444`, `--grey #858585`), `--max`.
- `src/styles/global.css` ports the 36px grid-line background, the noise
  overlay (`body::before`), and base typography (Inter / system
  sans-stack) verbatim.
- Segmented-LED countdown look, physical-button styling (glare, plinth,
  press states), `urgent`/`critical` timer classes and the
  `criticalPulse` keyframe are ported from `web/styles.css` into
  `CountdownDisplay.module.css` / `PressButton.module.css`.
- Every other component gets its own CSS Module, consuming the global
  tokens — no Tailwind, no component library, no gradients/glassmorphism,
  consistent with the "control room, not generic crypto" direction.
- Mobile: the giant-button center stage remains the dominant element;
  left/right columns and bottom strip stack below it on narrow viewports
  (breakpoint ported from existing responsive rules in `web/styles.css`).

## 9. Tooling / verification

- `eslint` (flat config, `typescript-eslint` recommended + `eslint-plugin-react-hooks`)
- `tsc --noEmit` for typecheck
- `vite build` for production build
- All three must pass with zero errors before the task is considered done;
  any failures are fixed, not suppressed.

## 10. Migration notes

- `web/about/index.html` stays a static HTML file (not part of the React
  bundle) — it's simple, has no dynamic state, and Vite serves/copies
  static HTML under its project root without modification. Its
  `../styles.css` reference is updated to point at the new built CSS
  output path once bundling changes it, or kept as a small standalone
  stylesheet importing the same tokens — decided at implementation time
  based on Vite's actual output filenames.
- `web/config.example.js` is kept as developer-facing documentation of
  the shape `scripts/configure.mjs` produces.
- `web/assets/button-token.png` moves to `web/public/assets/`.
- The old `web/app.js`, `web/styles.css` (root-level), and `web/index.html`
  are replaced by the Vite project files above; git history preserves the
  old version for reference (repo is being initialized as part of this
  work — see implementation plan).
